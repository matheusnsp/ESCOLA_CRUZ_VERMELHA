# EAD etapa 2 (o curso do lado do aluno): plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pelo link de teste, o aluno logado faz o curso inteiro (telas, quiz por sorteio, pré-teste, cenários com cronômetro) e o progresso fica salvo na conta.

**Architecture:** 4 tabelas novas de progresso (migração só cria). Regras sem banco em `src/lib/ead-progresso.js` (estado do curso, sorteio, correção) e `src/lib/ead-conta.js`. Acesso ao banco do progresso em `src/lib/ead-progresso-db.js`. As rotas e telas ficam no `src/routes/ead-teste.js` e em `src/views/ead-teste/`, com o layout da etapa 1. A conta é a do `/cadastro` e do `/login` de hoje.

**Tech Stack:** Node 22, Express 4, EJS, Prisma 5 / PostgreSQL 16, Zod 3, `node:test`.

**Spec:** `docs/superpowers/specs/2026-11-05-ead-aluno.md` (ler inteira, inclusive a nota de revisão no topo).

## Global Constraints

- Branch `ead-aluno` (sai de `ead-estrutura-conteudo`); PR para `main` **sem merge**, depois do #92. Só banco local.
- Migração só cria (`scripts/checar-migracao-ead.js` com as 4 tabelas novas na lista); nenhuma coluna em tabela existente.
- FK `AlunoCursoEad.usuarioId → Usuario` com **onDelete: Cascade** (a exclusão de conta apaga o `Usuario`).
- "Logado" = `req.session.usuarioId` com `req.session.papel === 'ALUNO'`. Outro papel é tratado como sem login.
- O gabarito nunca vai para o HTML antes da resposta. A correção é feita no servidor.
- Nenhum JavaScript inline (CSP). O único JS novo é `src/public/js/ead-cronometro.js`.
- Textos para o aluno em português. Os textos fixos da spec (§5) são usados como estão.
- O presencial não muda, exceto o `POST /cadastro`, que só volta para um `returnTo` que comece com `/ead-teste/`.
- Layout e 404 do link de teste da etapa 1 (sem rastreamento). Todas as páginas novas usam `_topo`/`_fim`.

## Review Focus

- Dois cliques rápidos em "Responder" (ou o botão de voltar e reenviar) não podem contar a mesma pergunta duas vezes nem pular uma. Task 3.
- Uma pergunta apagada no painel depois do sorteio não pode travar a tentativa aberta nem dar 500. Task 3.
- Uma tentativa ou cenário de outra pessoa, ou de outro curso (id trocado na URL), responde 404, mesmo com um código de link válido. Task 5.
- Um módulo bloqueado acessado pela URL direta (tela, quiz, pré-teste, cenário) não registra nada e volta para a página do módulo com o motivo. Tasks 4–6.
- O dia 7 é a fronteira: em `iniciadoEm + 7 dias − 1 min` ainda é sequência; em `+ 7 dias` já é livre. Task 2.

### Task 2: Regras sem banco

**Files:** Create `src/lib/ead-progresso.js`, `src/lib/ead-conta.js`, `test/ead-progresso.test.js`.

**Interfaces (Produces):**
- `estadoDoCurso(curso, progresso, agora: Date)` → `{ modulos: [{ id, numero, final, estado: 'bloqueado'|'disponivel'|'concluido', motivo: string|null, preTeste: 'disponivel'|'usado'|'indisponivel', topicos: [{ id, telas, telasVistas, quizAprovado, concluido }] }], percentual: number (0–100, inteiro), concluido: boolean, proximo: { tipo: 'tela'|'quiz'|'cenario'|'modulo', id } | null, sequencial: boolean }`.
  - `curso` = `{ modulos: [{ id, final, topicos: [{ id, telas: [{ id }], nPerguntasAtivas }], nPerguntasAtivas, cenarios: [{ id }] }] }` já na ordem do aluno.
  - `progresso` = `{ iniciadoEm: Date, telasVistas: Set<string>, tentativas: [{ tipo, moduloId, topicoId, aprovado, concluidaEm }], cenarios: [{ cenarioId, concluidoEm }] }`.
  - `proximo.tipo 'quiz'` tem `id` = topicoId. `'modulo'` é usado quando o próximo módulo disponível não tem telas.
- `DIAS_SEQUENCIAIS = 7`, `PRE_TESTE_MIN = 8`, `PRE_TESTE_MAX = 12`, `QUIZ_N = 3`.
- `sortear(ids: string[], n: number, evitar: string[] = [], aleatorio = Math.random)` → `string[]`.
- `tamanhoPreTeste(nAtivas: number)` → `number | null` (null se < 8).
- `corrigir(alternativas: [{ id, correta }], marcadas: string[])` → `boolean`.
- `aprovado(acertos, total, notaMinima)` → `boolean`.
- `ead-conta.js`: `cadastroIncompleto(usuario)` → `boolean` (spec §4.3).

- [ ] **Testes primeiro** (`test/ead-progresso.test.js`), com um curso montado à mão (M1 e M2 comuns com 1 tópico, 2 telas e 3 perguntas cada; M3 comum sem telas; F final com 1 cenário):
  - dia 0, nada feito: M1 `disponivel`, M2 `bloqueado` com motivo `'Abre depois do Módulo 1.'`, F `bloqueado` com `'Abre quando os outros módulos terminarem.'`, `proximo = { tipo: 'tela', id: <1ª tela de M1> }`, `sequencial: true`.

  - Pré-teste do M2 aprovado ⇒ M2 `concluido` sem telas vistas. Pré-teste reprovado ⇒ `preTeste: 'usado'` e M2 não concluído.
  - Fronteira: `agora = iniciadoEm + 7d − 60s` ⇒ M2 bloqueado. `= iniciadoEm + 7d` ⇒ M2 e M3 `disponivel`, `sequencial: false`, F continua bloqueado.

  - `sortear`: com `aleatorio` fixo, 3 ids distintos. Com 6 ids e `evitar` 3 deles, devolve os 3 outros. Com 4 ids e `evitar` 3, devolve 3 contendo o que sobrou. `n` maior que a lista ⇒ a lista toda, embaralhada.
  - `tamanhoPreTeste`: 7 → null, 8 → 8, 20 → 12.
  - `corrigir`: única certa/errada; múltipla com o conjunto exato ⇒ true, faltando uma ⇒ false, com uma a mais ⇒ false.
  - `aprovado(2, 3, 80)` false, `(3, 3, 80)` true, `(8, 10, 80)` true.
  - `cadastroIncompleto`: completo ⇒ false; cada um dos 8 campos vazio ⇒ true.

### Task 3: Acesso ao banco do progresso

**Files:** Create `src/lib/ead-progresso-db.js`, `test/ead-progresso-db.test.js` (pula sem `DATABASE_URL` local; requires no topo, como na etapa 1).

**Interfaces:**
- Consumes: Task 1 (modelos) e Task 2 (`sortear`, `tamanhoPreTeste`, `corrigir`, `aprovado`, `QUIZ_N`).
- Produces:
  - `carregarCursoParaAluno(cursoOnlineId)` → `{ co, curso }`: `co` com `curso.nome`, `notaMinimaQuiz` e os módulos completos para as views; `curso` no formato de entrada de `estadoDoCurso` (ordem do aluno, `nPerguntasAtivas` por tópico e módulo).
  - `garantirAlunoCurso(usuarioId, cursoOnlineId)` → `AlunoCursoEad` (upsert pelo unique).
  - `carregarProgresso(alunoCursoId)` → o `progresso` da Task 2.
  - `marcarTelaVista(alunoCursoId, telaId)` → void (idempotente: upsert).
  - `abrirQuiz(alunoCursoId, topicoId)` → `TentativaEad`: reaproveita a QUIZ aberta do tópico, se houver; senão sorteia `QUIZ_N` entre as ativas, evitando as `perguntaIds` da última tentativa do tópico.
  - `abrirPreTeste(alunoCursoId, moduloId)` → `TentativaEad | null` (null se já existe PRE_TESTE desse módulo ou se `tamanhoPreTeste` é null).
  - `tentativaDoAluno(tentativaId, alunoCursoId)` → tentativa com as perguntas que ainda existem (com alternativas e feedback), na ordem de `perguntaIds`; `null` se não for desse aluno.
  - `perguntaAtual(tentativa)` → a primeira pergunta sem resposta, ou `null`.
  - `responder(tentativaId, alunoCursoId, perguntaId, alternativaIds: string[])` → `{ correta, pergunta, fechou: boolean, tentativa }`. Num `$transaction` com `SELECT … FOR UPDATE` na tentativa (`tx.$queryRaw`): se `perguntaId` não for a pergunta atual, não grava nada e devolve `{ ignorada: true, tentativa }`. Senão anexa a resposta, soma o acerto e, se foi a última, fecha com `aprovado(acertos, total, notaMinima)` e `concluidaEm`.
  - `comecarCenario(alunoCursoId, cenarioId)` → `CenarioFeitoEad` (upsert que zera `decisaoAtual`, `erros`, `tempoSeg`, `concluidoEm` e grava `iniciadoEm = now()`).
  - `escolherNoCenario(alunoCursoId, cenarioId, decisaoId, opcaoId)` → `{ ignorada: true } | { certa, opcao, fechou, feito }`. Também com `FOR UPDATE`. A decisão precisa ser a atual (por ordem). Certa: `decisaoAtual + 1`; na última grava `tempoSeg` e `concluidoEm`. Errada: `erros + 1`.
  - `marcarCursoConcluido(alunoCursoId)` → void (grava `concluidoEm` se ainda estiver nulo).
- [ ] **Testes primeiro** (curso próprio criado e apagado no teste; usuário de teste criado e apagado):
  - `marcarTelaVista` duas vezes ⇒ 1 linha.
  - `abrirQuiz` duas vezes seguidas ⇒ mesma tentativa. Depois de fechada, a nova evita as anteriores quando o banco tem 6.
  - `responder` fora de ordem ⇒ `ignorada` e nada muda. Duas respostas **em paralelo** (`Promise.all`) para a mesma pergunta ⇒ só 1 conta.
  - Pergunta apagada depois do sorteio ⇒ `tentativaDoAluno` traz 2 de 3, `total` = 2 e a tentativa fecha normalmente. Todas apagadas ⇒ a tentativa aparece fechada e não aprovada.
  - `abrirPreTeste` com 8 ativas ⇒ 8 perguntas. Segunda vez ⇒ null.
  - `tentativaDoAluno` de outro aluno ⇒ null.
  - `escolherNoCenario`: errada ⇒ erros 1. Decisão que não é a atual ⇒ ignorada. Certa na última ⇒ `concluidoEm` e `tempoSeg` ≥ 0.
  - Excluir o usuário ⇒ o `AlunoCursoEad` dele some (cascata).
- [ ] `npm test` ⇒ falha. Implementar. `npm test` ⇒ passa. Commit "EAD aluno: acesso ao banco do progresso".
